HTB - Redeemer

Operating System: Linux
Tags: Redis, Vulnerability Assessment, Databases, Reconnaissance,
Anonymous/Guest Access

Information Gathering

First I started with a basic Nmap scan to identify open ports and services. This scan revealed no open ports, so I added -p- to scan all ports and removed -sC to minimize scan time. Only port 6379 appeared with the service name Redis.

$ nmap -sV -p- 10.129.1.14

Vulnerability Assessment

After some research, I learned that Redis is an in-memory database that can be interacted with using the redis-cli command. From there I used -h to specify a hostname to try and connect.

$ redis-cli -h 10.129.210.84

Exploitation

Normally, credentials would be required in order to access a Redis database, but it looks as if no authentication was set up. To confirm I was fully logged into the database, I ran the info command and viewed the output.

10.129.210.84:6379> info

Post-Exploitation

With full access, I researched Redis commands to select and view databases. Using info keyspace shows all the databases running, and select chooses which database you'd like to view.

10.129.210.84:6379> select 0

Now with the database selected, I used keys * to display all keys in the database and viewed the flag using get flag.

10.129.210.84:6379> get flag
