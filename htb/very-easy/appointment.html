HTB - Appointment

Operating System: Linux
Tags: Databases, Apache, MariaDB, PHP, SQL, Reconnaissance,
SQL Injection

Information Gathering

First I started with a basic Nmap scan to identify open ports and services. This scan revealed that the only service running was Apache on port 80.

$ nmap -sV -sC 10.129.91.173

Vulnerability Assessment

I brought up the Apache webpage and was met with a login form. To make sure there weren't any hidden paths, I used gobuster to brute force possible directories. Nothing from the output stood out to me, so I returned to the home page.

$ gobuster dir -u http://10.129.91.173/ -w Wordlists/SecLists/Discovery/Web-Content/raft-small-words.txt


Exploitation

I did not find any success with default credentials, so I began trying SQL injection payloads instead. As the password I entered ' OR '1'='1 and included any name in the username field. To my surprise, this bypassed the login page.

' OR '1'='1

Post-Exploitation

No post-exploitation was done, as the flag was immediately shown after the login page.
