HTB - Responder

Operating System: Windows
Tags: Apache, Local File Inclusion, NTLM, PHP, WinRM

Information Gathering

First I started with a basic Nmap scan to identify open ports and services. This scan revealed Apache on port 80 and Windows Remote Management on port 5985.

$ nmap -sV -sC 10.129.61.54

Vulnerability Assessment

I chose to visit the Apache webpage first, but couldn't connect due to a host error. To resolve this, I added unika.htb to my /etc/hosts file and visted the site again.



The webpage itself didn't offer much, but there was an option to change the page's language. Changing the language made a GET request for another HTML file.

Exploitation

With further enumeration, I discovered the language parameter was vulnerable to local file inclusion. There wasn't much to exploit with it, so I tested for remote file inclusion instead. Hosting a local webserver didn't receive any connections, so I used responder to create an SMB share.


$ sudo responder -I tun0

The target attempted to authenticate using NTLM, and my responder captured the username and hashed password of the administrator.

Post-Exploitation

Now that I found some credentials, I used John The Ripper to crack the hashed password so I could access the Windows Remote Management Service.

$ echo "Administrator::RESPONDER:[PASSWORD HASH]" > hash.txt
$ john -w=Wordlists/rockyou.txt hash.txt

With full admin credentials, I logged into WinRM using evil-winrm and accessed the host machine.

$ evil-winrm -i 10.129.61.54 -u administrator -p 'badminton' -P 5985

Many directories had nothing inside of them, but I ran into the user mike who contained the flag.
